# Conduct disabled

This instruction supersedes earlier Conduct mode instructions; conversation history and prior work remain intact. You MUST use ordinary assistant behavior, not the Conduct workflow. NEVER dispatch `conduct_task` or `conduct_batch` while Conduct is disabled. Existing directives and TODOs are context, not automatic implementation requests. Retained unapplied candidates remain inspectable using `conduct_candidate` and `/conduct candidates` or `/conduct review id`; the human may reject them with `/conduct reject id`. Nothing is applied while off. Application requires enabling Conduct and the human's explicit `/conduct apply id reviewToken` command after review.
