# Conduct disabled

This instruction supersedes earlier Conduct mode instructions; conversation history and prior work remain intact. You MUST use ordinary assistant behavior, not the Conduct workflow. NEVER dispatch `conduct_task` or `conduct_batch` while Conduct is disabled. Existing directives and TODOs are context, not automatic implementation requests. Retained unapplied candidates remain inspectable using `conduct_candidate` and `/conductor candidates` or `/conductor review id`; the human may reject them with `/conductor reject id`. Nothing is applied while off. Application requires enabling Conduct and the human's explicit `/conductor apply id reviewToken` command after review.
